# UI v2 — Futuristic Enterprise Redesign Plan (BrrrrDealAnalyzer frontend)

> **Execution model: inline.** Claude executes this plan directly in the session — no `superpowers` skills, no subagent-driven-development ceremony (no briefs, ledgers, per-task reviewers or dispatch prompts). Domain skills are still used where a task names them: `ui-ux-pro-max` (design direction, per-view page files, UX queries) and `gsap-skills` (`gsap-core`, `gsap-timeline`, `gsap-frameworks`, `gsap-performance`). Plain `Agent` subagents (no skill) are allowed only for the two uses named in §0 "Process". Progress is tracked in `docs/plans/2026-09-05-ui-v2-progress.md` (one line per finished task: task id, commit, gate result) and in git; after a context compaction, resume from that file and `git log`, never from memory. A copy of this plan is committed as `docs/plans/2026-09-05-ui-v2-plan.md` in Task 0.1.

**Goal:** Turn the v1 token-driven, light, conservative UI into a bold enterprise-fintech interface that ships **four switchable looks** — Obsidian Terminal, Aurora Glass, Neo-Brutal Fintech, Quiet Luxury (the four boards the user reviewed at https://claude.ai/code/artifact/4554ee25-5912-42b8-9694-19957ac0ae9c) — each in dark and light mode, selectable from a Settings panel in a new persistent app shell (sidebar, command palette, dashboard landing), with GSAP choreography and a Liquidity Timeline rebuilt as a grid dashboard with an SVG chart — while every network request, every written payload, every dialog string and every `data-testid` hook stays exactly as today.

**Architecture:** every component is written once against the **semantic token vocabulary** (colour, radius, border width, shadow, glow, blur, font families, motion durations/eases); a *look* is a CSS file that assigns those tokens under `html[data-look="<id>"]` with `.dark` overrides, so switching look or mode never touches a component. `src/design/theme.ts` owns both dimensions (`look` + `mode`) and loads the active look's fonts on demand. The 13 `Ui*` primitives gain 11 more; a new `src/components/shell/` layer wraps `RouterView`; views are re-templated freely (scripts may change **only** presentational state and class-string helpers). Behaviour is protected by the mechanical gates that survive from v1 (G1, G2, G5/G7, G6, G-HOVER, G8, GOLDEN-POLICY) plus a fast static hook inventory; G3/G4/G4b become advisory reports.

**Tech Stack:** Vue 3.5 `<script setup>`, Vite 7, TS 5.9 strict, Pinia 3 (frozen), vue-router 4 (frozen), PrimeVue 4.5 unstyled + global `pt`, Tailwind 3.4 (`darkMode:'class'`, `hoverOnlyWhenSupported`, `touch:` variant), GSAP 3.15.0 core only, Vitest 4, Playwright 1.62 (chromium, webkit, Mobile Safari, Mobile Chrome, chromium-motion), `@axe-core/playwright`. **Added (all self-hosted, lazy-loaded per look):** `@fontsource-variable/jetbrains-mono`, `@fontsource-variable/space-grotesk`, `@fontsource/unbounded`, `@fontsource-variable/fraunces`. Nothing else.

**Spec:** this file (§0 constraints, §1 design decisions, §2 gate policy, §3 phases/tasks, §4 Phase 3 execution protocol, §5 risks, §6 verification). Inputs it was derived from: `docs/ui-overhaul/decisions.md` (§7 follow-ups, §8 v2 intent), `docs/ui-overhaul/quality-snapshot.md`, `docs/superpowers/plans/2026-09-05-ui-v2-followup-prompt.md`, `design-system/brrrr-deal-analyzer/MASTER.md` (v1, to be superseded).

## 0. Global Constraints (binding for every task)

**Branching.** Start from the latest `origin/main` (`f21bfc9`, which contains v1 = PR #27 merge `9b1bd1f` **and** the modal-scroll bug fix). `git fetch origin && git checkout -b v2 origin/main && git tag ui-v2-baseline`. All work lands on `v2`, inline, in task order (§4 for Phase 3). Push `v2` + tag at each phase end. Final PR `v2 → main`.

**Frozen (byte-identical, gate G2 vs `ui-baseline`):** `frontend/src/{stores,api,utils,router,types,config}/**`. **Backend untouched (G1 vs `ui-baseline`):** everything outside `frontend/`, `docs/`, `design-system/`, `.superpowers/` incl. root `.gitignore`.

**Behaviour contract.** Every flow completes with the same requests (method, path, body — network goldens `frontend/e2e/golden/`), the same written data, the same `alert()`/`confirm()` strings. View scripts MAY change: presentational state (open/closed, tabs, hover, collapsed), pure class-string helpers (`getCashFlowColor` → token classes), imports of presentational components, `useId`/refs. View scripts MAY NOT change: fetch calls and their triggers, `watch` sources/options, debounces, settle window, `nextTick`/`scrollIntoView`, submission handlers, store calls, dialog copy, `defineProps/defineEmits` of existing components (new optional props are allowed on liquidity/deal components only when a task says so).

**Hooks are the contract.** Every `data-testid` referenced by `frontend/e2e/**/*.spec.ts` must exist in `frontend/src/**/*.vue` (Task 0.2 makes this a 1-second unit test). If a hook must move or a spec must change, it happens in a dedicated commit whose subject starts with `Golden update:` and touches only golden paths (§2).

**Not redesigned:** `views/RepsTracker.vue` and `components/reps/**` — Task 3.5 only makes them mount cleanly in the shell.

**Platform:** iOS Safari, Chrome on iPhone, desktop Chrome fully supported. `build.target`/browserslist unchanged (iOS ≥ 15). Rules carried from v1: `dvh/svh` units, `pb-safe-b`/`pt-safe-t`, ≥16 px inputs below 768 px, never transform a `position:fixed` overlay, hover reveals always paired with `touch:` (G-HOVER), no `maximum-scale`.

**Accessibility floor:** WCAG 2.2 AA — 4.5:1 text (both themes; `npm run audit:contrast` extended), 44 px primary touch targets (`min-h-11`), visible focus, `prefers-reduced-motion` honoured, **no new axe violations** vs the rule-keyed baseline (`e2e/golden/axe-baseline.json`), now scanned in both themes, at 1280 and 390 px, and with modals open.

**Motion:** GSAP core only (no plugins). Transforms/opacity only. No GSAP tween may outlive an interaction (`e2e/checks/no-live-tweens.spec.ts`) → ambient loops are CSS `@keyframes`, never `repeat:-1`, never `gsap.quickTo`. `page` preset stays enter-only and opacity-only. Never animate `VueDraggable` children; never animate size/padding/transform of any ancestor of `chart.container`.

**Portable paths (G8):** no absolute filesystem paths in tracked files.

**Process (inline).** Work through the tasks in order, one at a time, writing the code directly. Tests first where a task lists them (characterization and contract tests are written and run red/green before the code they protect). **Commit after every task** (`v2 <phase>.<task>: <what>`; trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`) and append one line to the progress file. User review **only at the end of a full phase** (never after a task); report progress as "stage X.Y of N". Browser suite (`npm run verify:ui -- --phase`) **only at the end of a full phase**; inside a phase run `npm run verify:ui -- --fast` (Task 0.1) plus the touched spec(s) on chromium after each task. Run gates in the foreground (10-min timeout), never a background monitor; kill stray `vite preview`/`serve_throwaway.py` before a run; never run a gate while a subagent is editing the same tree. Plain subagents (no skill), at most two uses: (a) the four look sheets of Task 1.1b may be written by parallel subagents, one file each, from the exact values in §1 Decision 2, reviewed and integrated by Claude; (b) one independent whole-branch code review before the final PR (Task 5.4). Everything else is written inline. Push `v2` at every phase end.

## 1. Design decisions (binding; recorded in MASTER.md by Task 1.5)

1. **Four looks × two modes, user-switchable.** Looks (ids are stable strings used in CSS, storage and tests): `obsidian` (Obsidian Terminal), `aurora` (Aurora Glass), `brutal` (Neo-Brutal Fintech), `luxury` (Quiet Luxury). Modes: `light | dark | system`. **Default: `aurora` + `dark`** (the most "futuristic, premium" of the four; changing the default is a one-constant edit in `theme.ts` + `index.html`). Stored in `localStorage['bw.look']` and `localStorage['bw.theme']`; applied as `<html data-look="…" class="dark">` + `style.colorScheme` by an inline pre-paint script in `index.html` (no flash) and by `src/design/theme.ts` at runtime; `resetChartTokenCache()` on every switch. `main.css` drops the hard `color-scheme: light` pin (`:root` and `.ui-select`). Components never reference a look; only token files do.
2. **Look token architecture.** `src/assets/tokens.css` keeps the token *names* and the v1 fallback values; each look lives in `src/assets/looks/<id>.css` and sets, under `html[data-look="<id>"]` (light) and `html[data-look="<id>"].dark`: colours (`--color-page/surface/surface-2/surface-3/line/fg/fg-muted/primary/primary-hover/primary-fg/accent/accent-2/positive/negative/warning/ring/glass/glass-line`), `--color-chart-1..8`, the 32 `--chart-*` literals, `--gradient-brand/surface`, `--glow-primary/accent/negative`, `--shadow-1..4`, `--blur-glass`, **`--radius-ctl/card/panel`**, **`--border-w`**, **`--font-display`**, `--font-mono`, `--dur-fast/base/slow`, `--ease-standard/emphasized/exit`, `--track-display`. Tailwind utilities (`rounded-card`, `border-ui`, `shadow-2`, `font-display`, `duration-base`, …) resolve to those variables, so a look can change radius, border weight, blur, type and tempo without any component edit. Look sheets per the reviewed board: obsidian = radius 6/6/8, border 1px, no shadow/glow/blur, cyan `#22D3EE`, display = mono, 140 ms; aurora = radius 12/16/20, glass blur 14px, glows, violet `#8B7CFF` + cyan + magenta, Space Grotesk, 420 ms spring; brutal = radius 2, border 2px, hard offset shadows (`--shadow-2: 6px 6px 0 rgb(var(--color-line))`), lime `#C6FF3D`, Unbounded 900, 200 ms; luxury = radius 10/12/16, warm charcoal, champagne `#D4B483`, Fraunces 600, 500 ms fades.
3. **Type.** Body: Inter Variable always (`fontFamily.sans` unchanged). `fontFamily.display` = `var(--font-display)`, `fontFamily.mono` = `var(--font-mono)`; numerals use `.numeric` (mono, tabular). Fonts are self-hosted and **loaded lazily per look** by `theme.ts` (`import('@fontsource-variable/space-grotesk')` etc. inside `applyLook`), so the first paint downloads Inter plus only the active look's faces; `font-display: swap`.
4. **Depth.** Surface tiers `surface < surface-2 < surface-3`, elevation `shadow-1..4`, glass panels (`bg-glass/60 backdrop-blur-glass border-glass-line`) **only as containers whose body text sits on an inner `bg-surface*` card** (in looks whose `--blur-glass` is 0 they render as plain surfaces); glow reserved for the primary CTA, the active nav item and focused KPI (zero-length in obsidian/brutal/luxury). Gradients from tokens only.
5. **Data-viz palette** `chart-1..8` and the 32 `--chart-*` literals defined per look and per mode (8 sets). `chartTokens.ts` keeps `CHART_FALLBACKS` (aurora-dark literals); `chartTokens.test.ts` keeps the 32-name SFC scan and the fallback check and **drops** the light≠dark literal table (the e2e chart-tokens/theme checks prove resolution in every look × mode instead).
6. **Iconography:** primeicons stays (`pi pi-*`), 20 px in nav, 16 px inline; every icon-only control is a `UiIconButton` with `label`.
7. **App shell:** desktop = CSS grid `[var(--sidebar-w)_1fr] / [auto_1fr]` with collapsible sidebar (15rem ↔ 4.5rem, **no width transition** — instant, so the chart's ResizeObserver never sees an animated ancestor), topbar (title, command trigger, mode toggle, settings button, connection status), `<main id="main" class="min-h-0 overflow-y-auto">`. Mobile (<lg) = sticky topbar + fixed bottom nav (`pb-safe-b`) + `<main>` padded for it. Command palette `Cmd/Ctrl+K`, client-side only (routes, look and mode actions, "Open settings"), `role="dialog"` + combobox/listbox semantics.
8. **Settings panel (Appearance).** The router is frozen, so Settings is a `UiDrawer` in the shell (`shell.settings`), opened from the sidebar footer gear, the topbar and the palette. Section "Look": four `LookPicker` cards (`shell.look.<id>`), each a live mini-preview rendered with that look's tokens (scoped `data-look` on the card), name, one-line description, radio semantics (`role="radiogroup"`, arrow keys). Section "Mode": Light / Dark / System segmented control (`shell.mode.<value>`). Section "Motion": Full / Reduced (`shell.motion.<value>`, stored `bw.motion`, feeds `motionEnabled()` alongside the OS setting). Choices persist immediately (no save button), apply instantly with the CSS cross-fade, and are announced via a polite live region.
9. **Landing → Dashboard.** `LandingPage.vue` keeps route `/`, `landing.offer`, the seven `landing.card.<title>` hooks with today's titles and hrefs, the four resource links, and `SendOfferModal`; it becomes a dashboard: greeting + `PortfolioStatsBar` in a height-reserved slot (`min-h-[var(--stats-bar-h)]`, kills CLS) + quick-action tiles + resource chips. No new fetches (`dealStore.portfolioStats` is already loaded by App.vue).
10. **PortfolioStatsBar** leaves the global column and renders only on the dashboard (no e2e spec asserts `statsbar.root` — verified). Its script (rAF count-up) and `statsbar.root` are untouched; template re-skinned as four `UiKpiCard`s.
11. **`app.status`** moves from a fixed dot into `shell/ConnectionStatus.vue` in the topbar (same testid, `role`, `aria-live`, the three exact title/aria-label strings, plus a visible label on `lg:`). The topbar is mounted on every route, including `/reps`.
12. **Liquidity** becomes a grid dashboard (§3 Phase 3 task C): chart panel full-width on top, DayDetail + sidebar below (sidebar becomes an inline collapsible section on narrow screens, so the two narrow-viewport specs can be un-skipped). `TimelineChart` is rewritten in **SVG** with the contract intact (props, `selectDay`, `centerOnToday`, keyboard semantics, `chart.container` tabindex 0, hover-over-selection, <4 px click vs pan, wheel pan) and all 32 `chartToken('…')` calls kept exactly once in its SFC script inside one theme-reactive `computed`.
13. **Script-emitted palette classes** in MyDeals/BoughtDeals (`stages[].color`, `getCashFlowColor`, `getPerformanceColor`, `getDSCRColor`, `getStageAccentColor`) are remapped to token classes (`text-positive/negative/fg/fg-muted`, `bg-surface border-line`, `border-l-chart-1..4`) — a presentational-only script change, required for theming and for the 3.77:1 contrast defect.
14. **Motion tiers per look.** Standard (existing presets/directives, applied everywhere) and Complex (six one-shot choreographies, §3 Phase 4). GSAP durations/eases are read from the active look's `--dur-*`/`--ease-*` at tween time (`src/motion/tokens.ts` becomes getter-based with `resetMotionTokenCache()` called by `applyLook`), so obsidian feels mechanical and aurora springy from the same code. Look/mode switch cross-fade is CSS, not GSAP.

- All five view batches are written inline on `v2`, serially, in the order **E → A → D → C → B** (smallest first; D before C because C's template consumes the modals; B last as the largest diff). No worktrees are needed: with no dispatch overhead, serial inline work is faster than parallel subagents at this size, and it keeps one author across all views.
- **Disjoint-file rule (still binding):** each Phase 3 task touches only its listed files + its `pages/*.md`. Shared files are frozen for the phase: `components.d.ts`, `ui/index.ts`, `ui/register.ts`, `tokens.css`, `assets/looks/*.css`, `design/{theme,looks}.ts`, `main.css`, `tailwind.config.js`, `src/test/setup.ts`, `e2e/golden/axe-baseline.json`, `src/motion/**`, `components/shell/**`. A view needing a new primitive creates it in its own folder (e.g. `components/liquidity/LiquidityStatRail.vue`); Task 5.3 may promote it. Check before each commit: `git diff --name-only HEAD` lists no frozen path.
- **Per-task gate:** `npm test && npm run build && npm run verify:ui -- --fast && npx playwright test --project=chromium <that task's specs>` (≈ 2–4 min), then commit and append to the progress file.
- Full 5-project suite runs **once**, at the phase end.

## 5. Risks specific to v2

| Risk | Mitigation |
|---|---|
| Sidebar + `h-dvh` boards squeeze/clip | shell `<main class="min-h-0 overflow-y-auto">`; board roots `h-full`, `overflow-x-auto`, `min-w-[16rem]` columns (Task 3.2); `my-deals-autosave.spec` on the Phase 2 mount |
| Modal scroll trap under new layout | modals are Teleported/fixed; `checks/modal-scroll.spec.ts` in Task 3.2's merge gate; body remains the only scroller |
| VueDraggable geometry inside new grid | `bought-deals-drag.spec` (chromium) in Task 3.2's gate; no wrappers/animations on draggable children |
| Theme flash / inconsistent first paint | inline pre-paint script + unit test tying `bw.theme` to `index.html`; `theme.spec` asserts `html.dark` at load |
| Dashboard breaks `landing.spec` | keep exactly the seven `landing.card.<title>` + `landing.offer` + `app.status`; network golden unchanged (no new fetch); `hooks-inventory` catches renames |
| `app.status` no longer fixed | topbar mounted on every route incl. `/reps`; same testid/role/strings |
| Chart rewrite drifts behaviour | characterization test written first (Task 3.3) + `liquidity.spec` arrow-key test + 32-token scan test |
| GSAP live tweens from ambient/loop effects | loops are CSS only; no `repeat:-1`, no `quickTo`; `no-live-tweens` on every route + palette + theme switch |
| Shared-file drift during Phase 3 | shared files frozen during Phase 3; primitives created in Phase 1; `git diff --name-only` check before every commit |
| Long inline session: context compaction or rate limit mid-task | commit after every task; progress file + `git log` are the recovery map; phase-end pushes; after a compaction, re-read the plan copy in `docs/plans/` and the progress file before touching code |
| Font payload on mobile (five families across four looks) | Inter static; each look's faces are lazy `import()` chunks loaded by `applyLook` only when that look is active; `font-display: swap`; budget checked in 5.2 |
| A component hard-codes one look (e.g. glass classes that look wrong in brutal) | components use tokens only; look sheets define every token (Task 1.1b test); after each Phase 2/3 task Claude spot-checks the view in obsidian and brutal (the two extremes) as well as the default; `theme.spec` axe runs in all 8 sets |
| Look switch mid-interaction leaves stale caches (chart colours, GSAP durations) | `applyLook`/`applyTheme` reset both caches and bump `themeEpoch`; the chart's colour `computed` depends on the epoch; `theme.spec` asserts chart tokens re-resolve after a switch |
