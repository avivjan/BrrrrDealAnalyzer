## 1. Guardrails (carried from v2, plus v3's own)

**Branch.** `ui-v3` off `origin/main` (`08fdd2c`); tag `ui-v3-baseline` before the
first commit. Progress file `docs/plans/2026-09-06-ui-v3-progress.md`, one row per
finished task, same format as v2.

**Never touched.**
- `BackEnd/`, `runtime.txt`, `.gitignore` — G1.
- `frontend/src/{stores,api,utils,router,types,config}` — G2, byte-identical.
- `src/views/LandingPage.vue`, `PortfolioStatsBar.vue`, `SendOfferModal.vue` — the dashboard is declared done. (One exception, see Phase 1 task 1.4: nothing in the file changes; the shell may add ambient *around* it.)
- `e2e/golden/*.json` network contracts. A redesign may not add, remove or reorder one request in any of the 23 recorded flows. This is the behaviour proof.
- `gsap` stays `3.15.0`, core only, no plugins (no ScrollTrigger: the app has one scroller, `<main>`, and `v-reveal` already uses IntersectionObserver; no Flip: reorder motion is `UiTransitionGroup` + CSS `.ui-move`). No new npm dependencies.

**Behaviour contract for `<script>` edits** (v2 §1, still policy even though G3/G4/G4b are advisory): a view's script may gain presentational state, class helpers, refs, and imports of presentational components. It may not change fetch calls or their triggers, `watch` sources/options, debounces or the 250 ms settle window, `nextTick`/`scrollIntoView`, submission handlers, store calls, dialog copy (`confirm()`/`alert()` strings), or existing `defineProps`/`defineEmits`.

**Every `data-testid` survives.** `src/test/hooks-inventory.test.ts` fails `npm test` if a hook the e2e suite references disappears from every template. The element carrying a hook may move or change tag; the string must exist. The full per-view hook list is in §7.

**Motion rules (hard).** Transforms and opacity only. Every entrance, stagger included, completes within 500 ms in every look (the e2e motion guard samples at +500 ms and requires zero live tweens). No tween outlives an interaction: ambient loops are CSS `@keyframes`, never `repeat: -1`, never `quickTo`. The `page` preset stays enter-only and opacity-only. Never animate `VueDraggable` children with GSAP or a transition group (board rows/columns are revealed, cards never are). Never animate size, padding or transform of any ancestor of `chart.container`. Every directive stays valueless (modifiers only), passive-listener, and releases tweens, listeners and inline styles on unmount. Reduced motion (`prefers-reduced-motion`, Settings → Motion: Reduced, `__BW_MOTION_OFF__`) short-circuits everything synchronously.

**Performance budget (new, measured at every phase end).**
- Bundle: main chunk delta ≤ +12 kB gzip over `ui-v3-baseline` (`vite build` output compared in the progress file). No new fonts.
- CLS ≤ 0.05 on every route (the dashboard's existing `PerformanceObserver` check is generalised in `e2e/checks/perf.spec.ts`, Phase 2).
- Long tasks: zero `longtask` entries > 50 ms during 3 s of idle on `/my-deals` and `/bought-deals` with 20 seeded cards, and during a chart pan.
- Compositing: `backdrop-filter` stays on at most the four shell surfaces (sidebar, topbar, page toolbar, bottom nav). Cards and columns are opaque. `will-change` is set by a directive only for the tween's lifetime.
- Hover effects gated on `(hover: hover)`; ambient paused on `(hover: none)`.

**Gate cadence.** `npm run verify:ui -- --fast` after every task (build, unit tests incl. hook inventory and contract tests, G-HOVER, G8, `check:looks`, `audit:contrast`). `npm run verify:ui -- --phase` at every phase exit (adds the five Playwright projects and the backend proofs). Goldens change only in `Golden update:` commits that touch nothing else; v3 needs exactly two (§8).

## 2. Design direction in one paragraph

Keep the token system and the four looks. What changes is *composition and motion*: each page gets its own header rhythm (eyebrow → display title → live figures) revealed in one ≤ 450 ms sequence, the two boards stop being stacked rows and become horizontal, connected stage columns, the two cards become two different objects (a *verdict* card and a *progress* card), and numbers count, lines draw, and lists reflow instead of snapping. Glass stays on the shell only. Motion is layered, not sprinkled: one entrance sequence per page, one hover language for all interactive tiles, one reflow language for all lists.

Phases 1 and 2 are foundations; 3–7 are the pages; 8 is closure. Each task names the files it touches and the gate it must pass. Effort is in half-days.

## 5. Decisions taken by default (say so to change them)

1. **Columns, not rows**, on desktop for both boards; rows/accordion below `lg`.
2. **Remove the toolbar cross-links** ("Bought Deals" on My Deals, "My Deals" on Bought Deals) along with the three back/home buttons. The sidebar, bottom nav and ⌘K palette carry every route.
3. **An "Advance →" quick action on the Bought card** when its checklist is complete. It reuses the store's existing `advanceStage`; drag and the modal button remain.
4. **Aurora light stays white glass**; only the dark block is corrected.
5. **Shell-level ambient on non-dashboard routes** in the looks that define one (Aurora drift, Luxury shimmer), CSS-only, paused on phones.
6. **The address filter on My Deals** is optional and off unless asked.
7. **`alert()`/`confirm()` copy stays** (behaviour contract). Restyling those as `UiModalPanel` dialogs would be a separate, agreed behaviour change with a golden update.

## 6. Risks

- **Tempo budget vs stagger.** Seven Bought columns × 0.06 s + a 0.32 s enter = 0.74 s, over the 500 ms guard. Columns therefore stagger at 0.03 s (0.5 s total in the slowest look) and the rail draw runs in parallel, not after.
- **Chart token test.** Dropping bars while keeping all 32 tokens read once each is a mapping exercise; do it first in Phase 6 and run `chartTokens.test.ts` before styling.
- **Contract tests on the cards** assert today's class strings and badge text; they are unit tests, not goldens, and change in the same commit as the card.
- **Hook inventory on `liquidity.back`** needs Golden update A (below) *before* task 1.4 lands, or `npm test` fails in between.
- **Backdrop blur is live only in Aurora** (the other looks set `--blur-glass: 0`). The four shell surfaces are the ceiling; nothing new gets `.glass`.
