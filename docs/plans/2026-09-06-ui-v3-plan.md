# UI v3 plan — execution plan (inline, per-task estimates, parallel batches)

Status: **approved 2026-09-06, executing.** Supersedes the first draft of this file (which carried a withdrawn "~15 days" human estimate). Branch: `claude/ui-ux-overhaul-plan-xmblf4`, created from `main` @ `08fdd2c` (tag `ui-v3-baseline`), plays the `ui-v3` role. Progress: `2026-09-06-ui-v3-progress.md`.

## Context

The user reviewed the UI v2 merge (`main` @ `08fdd2c`) and asked for six changes: (1) deal cards and the two board pages look like recoloured v1 and Bought Deals must become a real stage-flow tracker; (2) every page except the dashboard needs more motion/GSAP without hurting performance; (3) the liquidity chart should drop its bars and keep a line; (4) form field boxes are misaligned; (5) remove the back buttons (Liquidity, REPS); (6) Aurora Glass shows a white band at the side. Backend untouched, every existing flow preserved.

**Added on review (7): the Bought checklist must show every stage's tasks, not only the current stage's.** Today a deal shows only its current stage's checkboxes, so a critical task in a later stage is invisible until the deal is moved there; the user works around it by ticking the last box, moving forward to peek, and moving back. Requirement: all stages' checkboxes visible per deal, current stage expanded, the others collapsed and opened on click/scroll, and any stage's box tickable at any time.

Root-cause note for (7): the flat `completedSubstages` map already accepts any substage id (`toggleSubstage`, `boughtDealStore.ts:102`), so ticking a future stage's box needs no new store logic. What *would* lose those ticks is that both frozen store actions used for stage moves — `updateBoughtDealStage` (`:173`, called by drag at `BoughtDeals.vue:120,157`) and `advanceStage` (`:130`) — and the view's own `advanceEditingDeal` (`BoughtDeals.vue:355`) reset the map to `{}` on every stage change. The stores are G2-frozen, but the view can route stage moves through the generic `updateBoughtDeal` (`boughtDealStore.ts:47`, the same `PUT /bought-deals/{id}` autosave uses) with `completedSubstages` untouched. The recorded goldens already behave this way (`bought-deals-stage-select.json`'s PUT carries the map unchanged; the drag spec records no golden), so this is a view-only change with **no golden update**.

**Execution model:** inline in this session, like v2 (no superpowers skills — none are installed here, and v2 chose inline explicitly). One commit per task; progress in `docs/plans/2026-09-06-ui-v3-progress.md`. Task 1.0 replaces the committed draft plan (which carried a withdrawn "15 days" human estimate) with this one.

Root causes for (1)–(6), verified by building the app and screenshotting every route in Aurora light/dark and Luxury dark at 1440/390 px:

- **Aurora white band** — `frontend/scripts/design/looks.data.mjs:102`: Aurora's dark block sets `glass: '#ffffff'`; every other look uses a dark glass in dark mode. `.glass` (`main.css:196`) composites at 60 %, and the sidebar, topbar, board toolbars and bottom nav are `.glass`. Secondary: `::-webkit-scrollbar-track` is `surface-muted`, a lighter 8 px strip at `<main>`'s right edge in dark looks.
- **Field alignment** — four field anatomies in the same grids: `SliderField.vue` (value box in the label row, `gap-3`), `DaysUntilRefiField.vue` (a `UiButton` in the label row grows it), `MoneyInput`/`NumberInput` (`gap-1.5`, `text-sm`), raw `<select>`/`<input>` in both deal modals (`gap-1`, `text-xs`), liquidity forms mixing `text-lg pr-8`/`pr-24`/plain inputs.
- **Liquidity** — `TimelineChart.vue` draws the running balance twice: `<rect data-part="bar">` per day (`:451-461`) and the `balance-line` path (`:469`). Reserve floor never drawn. No test pins bars; `chartTokens.test.ts` requires all 32 `--chart-*` tokens read exactly once.
- **Back buttons** — `LiquidityTimeline.vue:409` (`liquidity.back`), `RepsTracker.vue:74` (`reps.back`), `AnalyzeDeal.vue:147` (`analyze.home`). `liquidity.back` is referenced in `e2e/flows/liquidity.spec.ts:115` (an annotation, not an assertion) — one `Golden update:` commit or the hook inventory test fails.
- **Cards/boards** — `DealCard.vue` and `BoughtDealCard.vue` share one skeleton; `MyDeals.vue`/`BoughtDeals.vue` share toolbar, stacked stage rows and modal body. Built-but-unused: `v-press`, `v-hover-lift`, `UiTransitionGroup`, and unregistered `UiTimelineRail`, `UiProgressRing`, `UiSparkline`, `UiTooltip`, `UiSegmented`, `UiDataTable` (`ui/register.ts:57-62`).

## Guardrails (unchanged from v2)

- Never touch: `BackEnd/`, `frontend/src/{stores,api,utils,router,types,config}` (G2), `LandingPage.vue`/`PortfolioStatsBar.vue`/`SendOfferModal.vue`, `e2e/golden/*.json` network contracts, the `gsap` pin (3.15.0 core, no plugins), no new deps.
- Script edits may add presentational state/class helpers/imports; may not change fetches, watchers, debounces, handlers, store calls, dialog copy, props/emits — **except the one agreed behaviour change in 4.0** (stage moves keep ticks), which changes no request method, path or recorded body.
- Every e2e `data-testid` survives (`src/test/hooks-inventory.test.ts`).
- Motion: transforms/opacity only; every entrance ≤ 500 ms; no tween outlives an interaction (ambient = CSS keyframes); never animate `VueDraggable` children or any ancestor of `chart.container`; directives valueless, passive, released on unmount.
- Perf budget at phase exits: main chunk ≤ +12 kB gz vs baseline, CLS ≤ 0.05 per route, zero >50 ms long tasks idle on boards with 20 cards, `backdrop-filter` only on the 4 shell surfaces.

## Where the time goes, and how it is cut

Sequential, one full gate per phase, the plan was ≈ 15 h 50 with task 4.0 and the checklist work added. Breakdown of that figure:

| Block | Sequential | Why |
|---|---|---|
| Gates | ≈ 3 h 20 | 8 × `--phase` (~12 min: build + 5 Playwright projects + backend proofs) + ~37 × `--fast` (~2 min: build + 1,300 unit tests + audits) |
| Phase 4 (Bought Deals) | ≈ 3 h 20 | the stage-rail board, column extraction, modal hero, ticks-preserving stage moves |
| Phases 1 + 2 (fixes, motion base) | ≈ 5 h 40 | many small tasks, each paying the fast gate |
| Everything else | ≈ 3 h 30 | cards, My Deals, liquidity, REPS/Analyze, closure |

Four cuts, none of which changes what ships or what is proven at the end:

1. **Four full gates instead of eight.** `--phase` runs after Phases 2, 5, 7 and 8 (v2 already merged its Phase 4+5 run). Every task still gets its unit/contract tests; the Playwright proof is still run on every phase's output before the next one builds on it. −50 min.
2. **Targeted tests per task, full fast gate per phase.** Inside a phase each commit runs `vitest run` on the touched suites plus the hook inventory (~30 s) instead of the full build; `verify:ui --fast` runs once at each phase end. Same tests, run once instead of per task. −45 min.
3. **Parallel worktree batches for disjoint files.** Independent tasks run as `Agent` subagents in `isolation: "worktree"` and merge back; nothing shares a file inside a batch, so there is no conflict resolution. Batches: **A** {1.5 fields, 1.7 liquidity forms, 1.8 alignment spec} · **B** {2.1 hero preset, 2.2 tilt, 2.6 guard specs} · **C** {3.1 DealCard, 3.2 BoughtDealCard} · **D** {6.x liquidity, 7.x REPS + Analyze}. Phases 4 and 5 stay sequential (they share `StageColumn.vue`). −3 h wall-clock.
4. **Fold 4.5 into 4.3 and cap docs.** The pipeline-editor pass is surface tiers + the segmented control already built; docs 8.2 is the decisions entry, primitives table and README motion row. −30 min.

**Result ≈ 10 h wall-clock** (sequential critical path: 1.0–1.4 → A → B → 2.3–2.5 → gate → C → 4.0–4.4 → 5.x → gate → D → gate → 8). The final `--phase`, the perf and alignment specs, and every unit and contract test are identical to the 15 h version.

Estimates below are agent wall-clock minutes per task including its targeted tests; ‖ marks a parallel batch.

## Appendix B — Functionality that must survive, per view (the checklist for each phase's review)

**My Deals**: load + deep link `?openDeal=&section=` (auto-open, scroll to results, `router.replace`); section tabs; Add Deal → `/analyze`; drag across five stages with optimistic update + revert; open modal; card delete/duplicate/move-to-bought (stage 3 only)/copy summary; modal: address inline edit, task, sqft/beds/baths, stage select, section select, Zillow/Photos links + open, design/crime/contact/niche, full `DealInputsForm`, live re-analyze (500 ms), autosave (2 s, settle, saved badge), save on close, sold/rent/sale comps add/delete/open, notes, footer move-to-bought/delete/duplicate/close, `UiSaveStatus`, PDF generate → in-app preview → download → close (blob revoked), header copy, coarse-pointer non-drag list.

**Bought Deals**: load deals + templates; BRRRR/FLIP tab; Edit Pipeline (editor: add/delete/rename/reorder stages and substages by arrows and drag, validation, orphan banner, save/save-and-close); drag ±1 stage with checklist gating and the alert listing missing substages; substage toggle on card (persists) and in modal; Advance to Next Stage; stage select override; delete/copy on card and in modal; the same modal editing, autosave, comps, notes and save status as My Deals.

**Liquidity**: fetch all + Mercury sync on mount; Today (centre), Mercury re-sync, Settings (opening balance, as-of date, reserve), Add Flow (one-time / recurring, inflow/outflow, dates, frequency, interval, ends after/on), edit from day detail or recurring list (virtual instance → source rule), delete with confirm for projected instances, simulation warning (hard/soft) with confirm/cancel, toast, day select by click and arrows, pan by drag/wheel, tooltip, sidebar toggle below `lg`, empty/loading/error states.

**REPS**: config status + banner, user tabs, stopwatch start/pause/finish → entry modal prefilled, manual entry, refresh, people manager, entries list with search/filter, upload flow inside the modal.

**Analyze**: BRRRR/FLIP toggle, every input, validation errors, Analyze & Save → name modal (address/stage/section) → save → My Deals, cancel.

**Shell**: sidebar collapse memory, ⌘K palette, Settings drawer (look, mode, motion), connection status, bottom nav, skip link.
